# 报告

`experiments/<name>/report/` 下每份报告的内容、结构与写作要求依本文件。

## 读者与目的

读者不是该领域专家，也不看单样本。他需要知道实验要回答什么问题、结果是什么，以及证据是否支持这个结果。

报告回答两问：

1. 这个实验要确定什么，为什么选择这些数据与方法。
2. 得出了什么结果，哪些证据支持，JEV 的调用代价是多少。

标题明确研究对象与要回答的问题，结果章提供回答该问题的证据，结论给出证据支持的判断。数据与方法的介绍应说明这些证据如何获得。

可读性优先：句子短，能用图不用表，能用表不用段落。粒度是分组、分布、比例、总量；除最小示例外，只对单个样本成立的观察不进报告。

## 写作顺序

1. 确定问题：写明研究对象、要测量或比较的内容，以及回答这个问题所需的指标。
2. 整理证据：核对数据和结果，区分直接支持结论的指标、辅助核对的分析与无关统计。
3. 设计图表：为每张图确定它要说明的关系、统计对象和比较基准，再安排展示顺序。
4. 组织正文：按读者所需的前置信息安排段落，先解释数据构成与必要概念，再给结果和判断。
5. 检查成稿：核对数字、图文对应和结论范围，删除重复或不能帮助理解的内容。

读者应能顺着正文理解目标、证据和结论，不必依赖附录或代码补全关键关系。

## 判断规则

1. 粒度：是否帮助回答本实验的问题。只对单个样本成立的不写（最小示例除外）。
2. 归属：是否落在「目的」「数据与场景」「结果与证据」「代价」「结论」之内。都不是的不写。
3. 作用：读者能否据此理解结果、判断证据是否充分。分析项目按用途选择，字段的存在本身不构成写作理由。
4. 结果化：数字只写结果值本身，不写得到它的算式；成本只写消耗量与总费用。
5. 对象化：写处理后的对象，不写处理过程。只写实验所用的样本，不写原有总量与剔除数量。
6. 行为：分别表述模型直接返回的选择或概率、按评测规则得到的对错，以及作者据此作出的推断。概率经阈值转换得到的类别属于评分结果；对模型行为原因的推测应有证据，并标明是推测。
7. 无套话：每次实验都会雷同出现的话不写。

## 报告目录

```
report/
├── REPORT.md     报告正文（英文），顶层唯一的文档；需要中文版时配 REPORT.zh.md
├── fig/          正文引用的图
├── scripts/      统计与绘图脚本
└── asset/        其他素材（中间表、示例原文等）
```

顶层只放报告文档，其余产出全部归入子目录；未用到的子目录不设，按需可增设其他子目录。fig/ 里的每张图都必须能由 scripts/ 里的脚本重新生成。

## Frontmatter

REPORT.md 以 YAML frontmatter 开头，六个字段缺一不可：

```yaml
---
title: 报告标题
date: YYYY-MM-DD
summary: 一句话摘要
samples: 样本数
input_tokens: 输入token数
cost: 费用
---
```

- `title` 写正文 H1 所用的短标题，按「标题」一节写。
- `date` 是最近修改时间，每次改报告时更新。
- `summary` 是描述实验目标或主要结果的一句话元数据，与正文结构分开管理。
- `samples`、`input_tokens`、`cost` 只统计 JEV 的结果：作答数、输入 token 总数（k 为单位，保留一位小数）与总费用（美元）。作答数核自结果记录，token 与费用核自响应的 `usage` 字段；不合并对照模型的消耗。

## 标题

`title` 与正文 H1 用同一个短标题，中英各写一个。

标题兼顾可读性与信息量：读者一眼可读完，且不打开文档即可知其中内容。标题写成一整句，或只给缩写名、上位词过泛，均不合要求。

- 标题不依赖文档：未读过文档、也不认识其数据集或项目的读者，由标题即可说出该文档考察什么。只给数据集名或缩写（`BBQ`、`GPQA Diamond`）不合要求，须在名称后带领域或题型（`BBQ 偏见敏感问答`、`GPQA Diamond 研究生级科学题`）。
- 标题以研究对象与考察内容命名。数据集名、场景或方法名只有能帮助界定研究内容时才加入，如 `GSM8K 小学数学应用题`、`泰坦尼克号生还预测`。
- 考察面多于两项时不全列：一到两项的全部写入，用 `场景：动作`（`波士顿房价：预测与比较`）；超过两项的，只取主导的一到两项，或概括为一个上位词（`工单分诊` 涵盖分类、退款与紧急度三项）。
- 标题用名词短语：不写「JEV 用四选一作答」一类主谓结构，不写「评估」「探究」「作答」一类不承载信息的词。
- 模型名在有助于界定研究对象时保留；仅重复仓库主题时省略。
- 术语按领域惯用说法写：`skill路由` 不译成「技能路由」；中文取读者熟悉的完整名称，`经典伦理困境` 优于 `伦理困境`，`小学数学应用题` 优于 `小学数学`；中英各按本语言的用法写，不逐字对译（`Titanic Survival` / `泰坦尼克号生还预测`）。

## 报告结构

正文不设「摘要」或「Abstract」，从实验目的开始。主体章节如下；结果章内部按本实验的证据顺序组织。

```
1 实验目的
2 数据集
3 最小示例
4 结果
5 结论
相关资料      有则设
附录          可选
```

| 章 | 必须回答 |
| --- | --- |
| 1 实验目的 | 要回答什么问题；为什么选这些数据与方法。有对照时，说明选择依据、比较条件和验证作用。用简短段落讲清楚 |
| 2 数据集 | 样本从哪来、有多少、由什么构成、按什么方式构造、覆盖哪些维度、维度如何划分。章节标题用该次场景的名称，数据集类实验即「数据集」。凡由本次分析补充的维度划分，必须声明它不是样本的原始标签 |
| 3 最小示例 | 一条真实样本的输入与输出，见「最小示例」节 |
| 4 结果 | 围绕图说明实验结果及证据，见「结果一章的组成」 |
| 5 结论 | 一段：直接回答实验目的，不逐项重述分析过程 |
| 附录 | 放不进正文的聚合表。没有就不设 |

数据集章先定义一条样本代表什么，再说明分组、配对、变体或重复测量之间的关系，最后给出各组数量与总量。原始对象数、输入条数和作答次数使用明确且一致的名称；同一对象的多个版本或多次测量不能自动视为独立样本。

介绍构造方式时，说明基于什么材料、改变哪些内容、形成什么任务。只展开影响结果解释的设计细节。

## 最小示例

- 从数据集中取真实的一条，展示发给模型的输入与模型返回的输出。
- 多变体（消融）实验每个变体各给一个示例，让读者对照变体差异。
- 长的输入截断并以省略号标出；输出只留关键字段。
- 示例语言随报告语言：中文报告的示例用中文，原始数据是英文时取一条翻译；英文报告同理。
- 示例是全报告唯一出现单样本的地方。

## 结果一章的组成

必写：

- 核心结果：直接回答实验问题的指标、必要的样本量，以及适用的基线或对照。总体指标与分组指标按解释需要选用；需要比较条件差异时，保留各条件的结果。
- 判据声明：一句说明判据来源，如「以数据集提供的标准答案为判据」。必要时交代弃答、概率阈值等会影响理解的统计口径，不展开字段比较的实现。
- 调用成本：只写 JEV 的输入 token、输出 token 和总费用，不记录对照模型的花销。

按需取用，采集到才写：

| 元素 | 取用条件 |
| --- | --- |
| 分组结果 | 分组比较有助于回答实验问题或解释总体指标 |
| 置信关系 | confidence、所选概率或 noul 输出值能为本实验目标提供证据 |
| 行为统计 | 输出行为影响结果的解释或使用 |

行为统计包括影响解释的输出瑕疵，如概率合计不等于 1、所选项与概率最高项不一致等。给出计数、占比及影响，不逐条列举。

结果小节按证据之间的关系排序：先呈现主要发现，再安排解释差异或核对结论的分析。附录只收录有查阅价值的补充材料。对照、稳定性或类型特色分析放在它们所支持的判断附近。

### 置信与概率分析

- 先说明要检验什么关系，再选择所选概率、confidence 或 noul 等测量量，明确它对应哪个答案或命题。
- 统计条件与问题对应。分析分值是否能区分作答质量，可按分值分档；分析条件变化的影响，应按相应条件分组。
- 汇总前检查含义是否一致。具体作答与弃答、不同题型的分值可能对应不同事件，需要分别统计或明确解释混合统计的含义。
- 均值、比例和分布同时给出统计对象与样本量。空组记为无数据，不用零代替；筛选后的结果只用于解释筛选范围内的回答。
- 置信程度、实际正确率和作答原因分别讨论。分值与正确率的关系需要用结果验证；分值本身不能证明回答是回忆、推理或猜测所得。

稳定性分析应说明改变了什么条件、结果如何变化，以及这对结论意味着什么。只保留解释结果所需的方法信息；概率、频率或区间均须明确统计对象与含义。

## 图与表

- 每张图配简短判断，说明它如何支持实验结论。正文不复述图内已有的颜色、坐标、图例和注释；需要读者先知道的数据构成放在图前。
- 精确数字只保留支撑判断所需的几项。图、表、段落不要重复呈现同一批数据，不强制为每张图另配表；表不放单样本。
- 图内文字从简；双语报告各配一套图，图内文字随报告语言（如 fig/en/ 与 fig/zh/）。
- 图形与要表达的关系匹配，如组间比较、分布、相关关系或随时间的变化。图的选择由分析问题决定。
- 缺失值与零值在图中区分。曲线不跨越缺失观测制造连续变化的印象。
- 对同一组中英文图统一检查样式与标注。圆滑连线时保留原始点，注明插值方式，不改变数据或统计估计，不引入额外峰谷。
- 图存 fig/，由 scripts/ 生成，正文用相对路径引用。

## 类型与特色部分

主体结构一致；特色部分按类型取用，放在结果章中最能支撑判断的位置。一个实验可属多个类型。

| 类型 | 特色部分 | 内容 |
| --- | --- | --- |
| 公开 benchmark | 能力定位 | 与公开榜单或文献分数对比，配定位图标出 JEV 的得分位置；对方作答形式不同、不直接可比时一句注明 |
| 消融 | 变体对比 | 各变体的指标与开销并列，差异即结论的来源 |
| 系统组件 | 系统位置 | 说明本实验在所属系统中的位置，互引其他组件实验 |

互有关联的实验（paper-qa、paper-classification、prompt-routing 三联）先统一查看设计与结果，再统一制作报告，口径与用词一致。

## 相关资料

报告不含参考文献章节。引用的外部材料集中在末尾「相关资料」，只保留与论证直接有关的外部来源；不列本项目的代码、数据、结果文件或分析脚本。关联实验的必要互引放在对应正文。固定格式，一行一条：

```
- 名称：URL
```

## 不应写

- 与当前判断无关的模型介绍：架构、泛泛的能力描述或字段说明。理解结果所需的概率含义应简要说明。
- 如何调用：端点、并发、重试、prompt、请求结构、脚本、参数。最小示例除外。
- 如何判分的实现：比较哪些字段、选项如何落到答案字母的机制。解释概率输出与阈值评分的区别不在此限。
- 数据准备的流程细节：原始总量、剔除标准与被剔样本、清理脚本。构造方式（选项怎么来、变体怎么分）要写。
- 单样本记录：编号、单样本的答案与模型选择、逐样本的差异说明。最小示例除外。
- 推算与单价：算式、单价、换算过程、每样本均值。
- 维度划分的细则规则。
- 局限一节，以及「未作重复采样」「不能推广到其他场景」这类话。
- 自我声明与免责。
- 造词与非日常表达。
- 只复述响应、不给判断的句子。
- 参考文献章节：外部材料一律进「相关资料」。

## 用词

全篇用规范书面语，同时保持易读：句子平实、动词优先、主动语态、一句一个意思；不堆名词、不留学名、不用口语与俚语。中文按中文的行文习惯写，不生硬翻译。

段落按读者的理解顺序展开，每句话提供新的事实、关系或判断。合并同义重复，删去没有信息量的过渡与笼统声明。解释结果的适用范围时，说明具体条件及其影响。

规范正文用通用词，报告按该次实验的对象命名：样本即题目、乘客、论文，输入即材料与设问，指标即准确率、一致率、MAE，维度即类别、价差桶、题型，第二测量量即所选概率、confidence、noul 输出值。同一报告内术语统一。

## 交付前自检

逐条回答，任一为「是」则重写。

- 有内容只对单个样本成立（最小示例除外）？
- 有把单次运行的观察写成因果或超出本场景的断言？
- 有内容在讲模型实现、调用方式或判分实现（最小示例除外）？
- 有数字给了算式、单价或推算过程？
- 有句子只在复述响应，没有给出判断？
- 有每次实验都会雷同出现的套话？
- 有自我声明、免责，或造词？
- 有口语、俚语、夸张说法，或名词堆砌？
- 标题、所用指标与结论回答的问题不一致？
- 缺 frontmatter 字段、漏了必要章节，或仍有正文摘要？
- 标题只有缩写名、上位词过泛，或写成了句子？
- 总量缺少构成说明，或统计单位、分组关系不明确？
- 分组或置信分析缺乏用途，或混合含义不同的测量量造成误读？
- 混淆模型输出、评分结果和作者推断，或没有证据就判断作答原因？
- 图表与正文反复罗列同一信息，或引入不能帮助判断结论的统计细节？
- 图缺少必要的题数信息，或 fig/ 里的图无法由 scripts/ 复现？
- 成本或页首元数据混入了对照模型的消耗？
- 写了参考文献章节，或在相关资料中列了项目内部文件？
- 数据集章缺了「维度划分由本次分析补充」的声明（有补充维度时）？
