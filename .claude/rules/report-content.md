# 报告内容

`experiments/<name>/report/` 下每份报告写什么、怎么排，依本文件。本文件管内容与结构，不管措辞风格。

## 读者与目的

读者不是该领域专家，也不看单样本。他要回答一个问题：JEV 在这个场景所代表的领域里，能力如何。

报告回答两问：

1. 这个实验为什么做、在什么场景下做的。
2. JEV 在这个场景里能力如何、代价多少。

可读性优先：句子短，结构固定，能用图不用表，能用表不用段落。粒度是分组、分布、比例、总量；除最小示例外，只对单个样本成立的观察不进报告。

## 判断规则

1. 粒度：是否回答「这个领域的能力如何」。只对单个样本成立的不写（最小示例除外）。
2. 归属：是否落在「目的」「场景」「能力与代价」「结论」之内。都不是的不写。
3. 行动：读者能否据此判断分数可不可信、能不能迁移、要不要复现、confidence 可不可用。不能的不写。
4. 结果化：数字只写结果值本身，不写得到它的算式；成本只写消耗量与总费用。
5. 对象化：写处理后的对象，不写处理过程。只写实验所用的样本，不写原有总量与剔除数量。
6. 行为：模型一侧只写答了什么（选择、概率、对错），不写为什么这么答。
7. 无套话：每次实验都会雷同出现的话不写。

## 报告目录

```
report/
├── REPORT.md     报告正文（英文），顶层唯一的文档；需要中文版时配 REPORT.zh.md
├── fig/          正文引用的图
├── scripts/      统计与绘图脚本
└── asset/        其他素材（中间表、示例原文等）
```

顶层只放报告文档，其余产出全部归入子目录；未用到的子目录不设，按需可增设其他子目录。fig/ 里的每张图都必须能由 scripts/ 里的脚本重新生成。

## Frontmatter

REPORT.md 以 YAML frontmatter 开头，三个字段缺一不可：

```yaml
---
title: 报告标题
date: YYYY-MM-DD
summary: 一句话摘要
---
```

- `date` 是最近修改时间，每次改报告时更新。
- `summary` 一句话说清测什么能力、在什么场景，如「测试 JEV 模型能否回忆 1996 至 2024 年八届美国总统大选的胜选者」。

## 报告结构

顶层章节固定，不增删；类型特色部分作为结果章的末尾小节加入。

```
摘要
1 实验目的
2 数据集
3 最小示例
4 结果
5 结论
相关资料      有则设
附录          可选
```

| 章 | 必须回答 |
| --- | --- |
| 摘要 | 一段：目的、场景、样本量、结果、判断 |
| 1 实验目的 | 测 JEV 的什么能力；为什么选这个场景与数据集。通俗语言，两三句，如「正因为要测 JEV 能否直接做数值回归，才选经典的波士顿房价数据集」 |
| 2 数据集 | 样本从哪来、有多少、由什么构成、按什么方式构造、覆盖哪些维度、维度如何划分。章节标题用该次场景的名称，数据集类实验即「数据集」。凡由本次分析补充的维度划分，必须声明它不是样本的原始标签 |
| 3 最小示例 | 一条真实样本的输入与输出，见「最小示例」节 |
| 4 结果 | 在这个场景下表现如何、代价多少，见「结果一章的组成」 |
| 5 结论 | 一段：对该领域能力得出什么判断 |
| 附录 | 放不进正文的聚合表。没有就不设 |

## 最小示例

- 从数据集中取真实的一条，展示发给模型的输入与模型返回的输出。
- 多变体（消融）实验每个变体各给一个示例，让读者对照变体差异。
- 长的输入截断并以省略号标出；输出只留关键字段。
- 示例语言随报告语言：中文报告的示例用中文，原始数据是英文时取一条翻译；英文报告同理。
- 示例是全报告唯一出现单样本的地方。

## 结果一章的组成

必写：

- 整体结果：样本量、总体指标，必要时给区间；给基线或随机水平的参照值。
- 判据声明：一句说明判据来源，如「以数据集提供的标准答案为判据」。不写判据的实现。
- 置信关系：凡采集到第二测量量（confidence、所选概率、noul 输出值），必写分档指标并配关系图，一句说明用的是哪个量。这一节要让读者判断 confidence 到底有什么用。
- 调用成本：输入 token、输出 token、总费用。

按需取用，采集到才写：

| 元素 | 取用条件 |
| --- | --- |
| 分组结果 | 样本带可分的维度 |
| 行为统计 | 有可聚合的行为数据 |

行为统计包括零星输出瑕疵（概率合计不等于 1、所选项与概率最高项不一致等）：只给计数与占比，不逐条列。

同一章内依次为：整体结果、分组结果、置信关系、行为统计、调用成本、类型特色部分。

## 图与表

- 每张图配一句判断；图不替代表格的精确数字，表不放单样本。
- 图内文字从简；双语报告各配一套图，图内文字随报告语言（如 fig/en/ 与 fig/zh/）。
- 标配图：置信-指标关系图（分档指标加分布）。benchmark 型再加能力定位图。
- 图存 fig/，由 scripts/ 生成，正文用相对路径引用。

## 类型与特色部分

主体结构一致；特色部分按类型取用，作为结果章末尾小节。一个实验可属多个类型。

| 类型 | 特色部分 | 内容 |
| --- | --- | --- |
| 公开 benchmark | 能力定位 | 与公开榜单或文献分数对比，配定位图标出 JEV 的得分位置；对方作答形式不同、不直接可比时一句注明 |
| 消融 | 变体对比 | 各变体的指标与开销并列，差异即结论的来源 |
| 系统组件 | 系统位置 | 说明本实验在所属系统中的位置，互引其他组件实验 |

互有关联的实验（paper-qa、paper-classification、prompt-routing 三联）先统一查看设计与结果，再统一制作报告，口径与用词一致。

## 相关资料

报告不含参考文献章节。引用的外部材料集中在末尾「相关资料」，固定格式，一行一条：

```
- 名称：URL
```

## 不应写

- 模型是什么：架构、能力描述、字段含义。
- 如何调用：端点、并发、重试、prompt、请求结构、脚本、参数。最小示例除外。
- 如何判分：比较哪些字段、选项如何落到答案字母的机制。
- 数据准备的流程细节：原始总量、剔除标准与被剔样本、清理脚本。构造方式（选项怎么来、变体怎么分）要写。
- 单样本记录：编号、单样本的答案与模型选择、逐样本的差异说明。最小示例除外。
- 推算与单价：算式、单价、换算过程、每样本均值。
- 维度划分的细则规则。
- 局限一节，以及「未作重复采样」「不能推广到其他场景」这类话。
- 自我声明与免责。
- 造词与非日常表达。
- 只复述响应、不给判断的句子。
- 参考文献章节：外部材料一律进「相关资料」。

## 用词

全篇用规范书面语，同时保持易读：句子平实、动词优先、主动语态、一句一个意思；不堆名词、不留学名、不用口语与俚语。

规范正文用通用词，报告按该次实验的对象命名：样本即题目、乘客、论文，输入即材料与设问，指标即准确率、一致率、MAE，维度即类别、价差桶、题型，第二测量量即所选概率、confidence、noul 输出值。同一报告内术语统一。

## 交付前自检

逐条回答，任一为「是」则重写。

- 有内容只对单个样本成立（最小示例除外）？
- 有把单次运行的观察写成因果或超出本场景的断言？
- 有内容在讲模型实现、调用方式或判分方式（最小示例除外）？
- 有数字给了算式、单价或推算过程？
- 有句子只在复述响应，没有给出判断？
- 有每次实验都会雷同出现的套话？
- 有自我声明、免责，或造词？
- 有口语、俚语、夸张说法，或名词堆砌？
- 缺 frontmatter 字段，或顶层章节有增删，或漏了必写项？
- 采集到第二测量量却缺置信关系图，或 fig/ 里的图无法由 scripts/ 复现？
- 写了参考文献章节？
- 数据集章缺了「维度划分由本次分析补充」的声明（有补充维度时）？
