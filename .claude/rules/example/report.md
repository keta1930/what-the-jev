# 报告

`example/<name>/` 下的 `README.md` 与 `README.zh.md` 按本文件写作。主要参照 `example/us-election/` 的双语 README。多种答案类型的说明参照 `example/ticket-triage/`。

读者没有读过数据集，也不会打开数据文件。README 要让他读完后知道：示例问模型什么、模型答了什么、代价多少、怎么重跑。

## Frontmatter

`README.md` 与 `README.zh.md` 各自以 YAML frontmatter 开头，六个字段缺一不可：

```yaml
---
title: 示例标题
date: YYYY-MM-DD
summary: 正文第一句
samples: 样本数
input_tokens: 输入token数
cost: 费用
---
```

- `title` 写正文 H1 所用的短标题，按「标题」一节写。
- `date` 写最近修改日期，新建与每次修改都写当日。
- `summary` 写本示例测什么的一句话，与正文第一句的文本相同。
- `samples`、`input_tokens`、`cost` 写本文件对应语言那份结果的样本数、输入 token 总数（k 为单位，保留一位小数）与总费用（美元）；英文 README 取 `responses.jsonl`，中文 README 取 `responses_zh.jsonl`，数值核自各响应的 `usage` 字段。

## 标题

`title` 与正文 H1 用同一个短标题，中英各写一个。

标题兼顾可读性与信息量：读者一眼可读完，且不打开文档即可知其中内容。标题写成一整句，或只给缩写名、上位词过泛，均不合要求。

- 标题不依赖文档：未读过文档、也不认识其数据集或项目的读者，由标题即可说出该文档考察什么。只给数据集名或缩写（`BBQ`、`GPQA Diamond`）不合要求，须在名称后带领域或题型（`BBQ 偏见敏感问答`、`GPQA Diamond 研究生级科学题`）。
- 标题按考察内容命名，不照搬目录名：对象有公开名称的，在名称后加限定词（`GSM8K 小学数学应用题`）；没有公开名称的，用其场景与测法（`泰坦尼克号生还预测`、`波士顿房价：预测与比较`）。
- 考察面多于两项时不全列：一到两项的全部写入，用 `场景：动作`（`波士顿房价：预测与比较`）；超过两项的，只取主导的一到两项，或概括为一个上位词（`工单分诊` 涵盖分类、退款与紧急度三项）。
- 标题用名词短语：不写「JEV 用四选一作答」一类主谓结构，不写「评估」「探究」「作答」一类不承载信息的词。
- 标题不含模型名：仓库与站点均以 JEV 为主题，重复该名称不增加信息。
- 术语按领域惯用说法写：`skill路由` 不译成「技能路由」；中文取读者熟悉的完整名称，`经典伦理困境` 优于 `伦理困境`，`小学数学应用题` 优于 `小学数学`；中英各按本语言的用法写，不逐字对译（`Titanic Survival` / `泰坦尼克号生还预测`）。

## 结构

按此顺序成文。

1. 示例目标：用一句话说明测什么，紧接着交代样本规模与场景。有对照样本时，说明相同内容与改变的条件。
2. 提问：逐条给出自然语言问题、答案类型与答案形态。封闭选项与等级必须列全，文本取自对应语言的数据集；相同定义可合并列示。
3. 示例：取数据集中的一条样本，展示发给模型的输入与返回的输出，见「示例」一节。
4. 结果：先报告返回情况与主要结果，再按问题解释判断及关键对照，见「结果」一节。
5. 成本：以 `## Cost`（英文）与 `## 成本`（中文）独立成节，报告对应语言的输入与输出 token 总数、总费用。需要说明对照样本的开销时再补充逐项用量，不默认罗列每条样本。
6. 复现：给出可直接执行的命令，并说明配置实际读取的数据和写入的结果路径。配置同时处理双语时，两组路径都写全。

## 示例

放在「提问」与「结果」之间，以 `## Minimal Example`（英文）与 `## 最小示例`（中文）为标题。

- 选择能直接展示主要发现的真实样本，如条件变化后的回答、识别失败或不同问法的判断差异。输入与对应输出各为一个 JSON 代码块。
- 输入保留原始 `state` 与 `questions`，省略 `model`。长输入可截断，保留部分必须取自原文，并以省略号标明省略位置；说明实际请求使用完整输入。
- 输出保留 `answers` 与 `usage` 的关键字段。已在提问中列全的 `legend` 可省略，答案值、概率与用量不得改写。
- 多个答案可各占一行，`usage` 可用一行展示；避免一个简单答案占用大量行，也不把整个代码块压成一行。
- 示例语言随 README 语言：英文 README 取 `data/dataset.json` 与 `result/responses.jsonl`，中文 README 取 `data/dataset_zh.json` 与 `result/responses_zh.jsonl`；数据集原文不改写、不翻译。
- 代码块后简短说明模型判了什么，与参考答案或题目条件是否相符；无参考答案时按给定条件解释，不宣称答对。
- 示例是正文唯一展示原始输入与输出的地方。

## 结果

- 先说明成功与失败样本量。有参考答案时，按问题或答案类型报告一致情况；比例须写清分母与失败样本是否计入。无参考答案时说明一次，再依据输入与判定标准解释结果。
- 解释判断及其依据：模型选择了什么、落在哪个等级、为何与参考或题目条件相符或不符。依据来自样本内容、给定标准或提供的材料，不从答案推断模型内部机制。
- 有对照时，围绕改变的条件或问法组织结果。表格保留支撑对照的答案、概率及响应中提供的 `confidence`，正文解释差异；不重复逐行朗读表格，不为罗列全部响应字段另设长表。
- 区分各类型的含义。`choice` 的概率比较互斥候选项；逐项 `noul` 是不同命题的肯定概率，接近 0.5 表示判断不明确，不能当作同一个候选分布。`score` 按给定等级解释数值。`confidence` 表示选项分布的集中程度，不是答案正确率。
- 保留概率答案。`noul` 不改写成布尔值，也不把命题概率解释为任务通过率或人群赞成比例。同一题另有逐项是非问题时，即使选择题答对，也须检查是非判断是否支持错误命题或留有不确定性。
- 核对参考答案与题目条件是否一致。参考记录实际结果，而题目另有限定信息时间等条件时，分别说明参考一致性和条件下的合理判断，不将两者混为同一正确率。选项合并多种含义时，不将其中某一含义当成模型已明确给出的判断。
- 结论限于已提供的样本与输入形式。识别失败且候选概率分散，不足以证明等同随机猜测；全为攻击的样本不能说明正常输入的误报表现。只写影响当前解读的具体范围，省略泛泛的统计免责声明。

## 约束

- 标识符保持原值。字段名、选项键、枚举值、答案类型名用代码格式原样写出，不译成中文。
- 引用对应语言的数据原文。等级文本、选项描述与判断条件直接抄该数据集的 `criteria`，不改写、不翻译。材料本身为英文时，中文 README 也保留原文并说明材料语言。
- 只给结果，不给推算。写结果值本身，不写得到它的算式。
- 数值核自对应语言的结果文件。不凭印象概括，不共用两种语言的概率、用量或合计费用。字段随答案类型变化，例如 `noul` 不返回 `confidence`。
- 只保留帮助理解任务、判断、代价与复现的文字。类型定义说明一次，表格与正文各有用途；删除重复结论、自我声明和未经材料支持的背景扩展。
- 书面语，无人称。不用「你」「我们」，不用口语。
- 并列内容用行或用表，不用分号串成长句。Markdown 中相邻行会并成一段，分行需用空行隔开。

## 交付前自检

逐条回答，任一为「是」则重写。

- 结果只在复述响应，未说明判断、依据或关键差异？
- 表格与正文重复逐项列数，或成本默认罗列全部样本却不解释开销差异？
- 有标识符被译成中文，或有数据原文被改写？
- 给了算式、推算过程或单价？
- 数值未经对应语言的结果文件核对，或混用了双语结果、合计费用？
- 将 `noul` 写成布尔值、任务通过率或人群比例，或将 `confidence` 当成正确率？
- 将参考不一致直接算作答错，却未核对参考与题目条件，或无参考答案仍宣称答对？
- 根据单次响应推断模型内部机制，或概括超出样本与输入形式的支撑？
- 出现「你」「我们」或口语词？
- 缺 frontmatter 字段，或 title 与 H1、summary 与正文第一句不一致？
- 标题不合「标题」一节：含模型名，只有缩写名或上位词过泛，或写成了句子？
- 缺示例，所选样本无法展示主要发现，或示例的位置、标题、字段取舍不合「示例」一节？
- 示例的输入与输出未经对应数据集与结果文件核对，或截断未标位置、保留部分不来自原文？
- 缺独立成本节，或复现说明未覆盖配置实际处理的数据与结果路径？
