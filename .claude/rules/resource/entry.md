# 条目

`resource/` 下的新增与更新按本文件执行。参考实现：`resource/open-source-models/kev.md` 与 `kev.zh.md`。

## 新增条目

1. 判定收录：只收项目与模型，不收论文与文章。优先收录成熟、可验证、资料完整的项目；成熟度不足的项目经确认后收录，现状（MVP、实验性）如实写入【适用】。
2. 归入目录：closed-source-models、open-source-models、use-cases、integrations、tools、benchmarks。新增分类时先建目录，并同步两份 README 的分类表。
3. 创建文件对：`<slug>.md`（英文）与 `<slug>.zh.md`（中文）。slug 在 `resource/` 内唯一，小写连字符；与已收录项目同名时加所有者前缀区分。
4. 写 frontmatter：`title` 与正文 H1 一致；`updated` 为本次修订日期。
5. 写正文：四段依次为【定位】【功能】【特点】【适用】，英文对应 **Positioning** / **What it does** / **Characteristics** / **When to use**，标签后不加冒号。中文 350-500 字，英文 250-350 词。
6. 写 `## Links`：一至四条公网链接，链接文本标注类型（GitHub、Website、Docs、HF、PyPI、npm 等）。
7. 更新索引：README.md 与 README.zh.md 的对应分类表各加一行（标题、路径、简介）。英文索引只链 `.md`，中文索引只链 `.zh.md`。

## 更新条目

- 改动任一语言版本后，另一语言版本同步相同改动，frontmatter `updated` 改为当日。
- 上游变化（改版、下线、链接失效）先访问核实，再改条目；下线项目删除文件对并同步两份索引。
- 新核实的事实替换旧的转述信息，来源标注随之更新。

## 写作约束

- 只写公网来源的事实，不引用本地路径。收录前实际访问条目的核心链接；仅搜索摘要支撑的信息不写入。
- 中性陈述，不用评价词（领先、严谨、出色、代表案例、representative、worthwhile 等）。
- 性能与对比数字带来源标注：自报、官方、第三方、或榜单名加版本号。二手信息以"据报道"转述。
- 许可证、价格、日期、技术参数只写在【功能】【特点】中有信息价值的位置，不逐项罗列。
- 【适用】写明适合与不适合的场景。
- 标识符保持原值：模型 ID、接口路径、字段名、榜单名用代码格式原样写出，不翻译。

## 交付前自检

任一为「是」则先改再交付。

- 只改了一个语言版本，或 `updated` 未改？
- 有链接未实际访问过，或有仅摘要支撑的内容？
- 有数字缺来源标注，或有评价词？
- 两份 README 索引未同步？
